# RFC-0007 — Plugin Resolution User Experience

## Status

Accepted

## Summary

RFC-0007 defines the user experience for plugin resolution diagnostics in FamilyOS CLI.

It transforms structured plugin resolution diagnostics into readable, actionable terminal output while preserving Clean Architecture boundaries.

The architecture and implementation defined by this RFC are complete and validated.

---

---

## Key Decisions

- Diagnostics remain framework-independent.
- Typer remains confined to `interfaces/cli`.
- `TerminalFormatter` builds terminal text.
- `DiagnosticCliRenderer` is the CLI presentation adapter.
- The renderer returns a string and does not print.
- Commands coordinate application services and presentation.
- `CommandContext` exposes application capabilities, not renderers.
- `ApplicationContainer` does not construct CLI presentation objects.
- Exit codes remain an interface policy.
- Optional terminal styling remains an interface-layer concern.
- Plain-text diagnostic rendering remains deterministic.
- `DiagnosticPresentationService` is rejected.

---

## Rejected Component

The proposed `DiagnosticPresentationService` is not part of the accepted architecture.

It provided no unique responsibility and introduced an undesirable dependency cycle between presentation and rendering responsibilities.

The accepted architecture keeps the dependency direction:

```text
ResolutionExplanation
        |
        v
TerminalFormatter
        |
        v
DiagnosticCliRenderer
```

No `DiagnosticPresentationService` implementation remains in the repository.

## Implemented CLI Behavior

Plugin resolution is exposed through the FamilyOS CLI.

The command layer:

- parses canonical plugin dependency expressions;
- invokes the plugin resolution pipeline;
- converts resolution failures into structured diagnostics;
- explains those diagnostics;
- renders terminal-oriented diagnostic text;
- writes diagnostics through the CLI output boundary;
- returns a non-zero exit status for expected resolution failures;
- avoids tracebacks for expected resolution failures.

Successful resolution produces normal CLI success output.

Resolution failures produce readable and actionable diagnostics.

---

## Presentation Boundary

The diagnostic subsystem remains independent from Typer.

Typer is confined to the CLI interface layer.

The ecosystem diagnostic packages do not import the CLI interface package.

The CLI may depend on ecosystem diagnostics, but ecosystem diagnostics do not depend on the CLI.

This preserves the intended dependency direction and prevents presentation framework concerns from entering the diagnostic model.

---

## Terminal Styling

Terminal styling is optional.

Styling does not alter diagnostic models, explanations, or the deterministic plain-text representation.

Environments without color remain supported.

Plain-text behavior remains available for deterministic automated testing.

---

## Exit Policy

Plugin resolution failures are expected CLI failures.

When resolution diagnostics contain failures, the CLI:

1. renders the complete diagnostic output;
2. preserves deterministic diagnostic ordering;
3. writes diagnostic output through the CLI output boundary;
4. terminates with exit code `1`.

Successful plugin resolution terminates normally with exit code `0`.

Expected resolution failures do not produce Python tracebacks.
